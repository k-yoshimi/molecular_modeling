結晶構造予測（CSP）ガイド
=========================

分子の構造（孤立分子の座標）だけから、分子結晶の候補構造を作り、
GFN2-xTB（既定）または機械学習ポテンシャル OrbMol-v2 で緩和してエネルギー順に並べ、
実験の CIF と答え合わせをするための手順書です。
OS-2SMe のように、O と S の入れ替わり（flip）がある分子結晶を想定していますが、
一般の有機分子結晶にも使えます。

   :local:
   :depth: 2

インストール
------------

このガイドのコマンドは、すべてリポジトリの最上位（``pyproject.toml`` のあるディレクトリ）で実行します。
Python 3.11 以上が必要です。

.. code-block:: bash

   python -m venv .venv          # 仮想環境がまだなければ最初に 1 回
   source .venv/bin/activate
   pip install -e ".[csp]"

``csp`` extra で PyXtal、tblite（GFN2-xTB）、pymatgen が入ります。CSP が使う spglib も
これらと一緒に入ります。本体の依存ライブラリには含まれません。
どれかが import できないと、``molecular-modeling-csp`` は候補生成を始める前に止まり、
足りないパッケージ名と ``pip install -e ".[csp]"`` の案内を出します。

機械学習ポテンシャル OrbMol-v2 で緩和したいとき（`緩和の計算方法の選び方`_\ ）は、代わりに ``csp-ml`` extra を
入れます。``csp`` の内容もすべて含みます。

.. code-block:: bash

   pip install -e ".[csp-ml]"    # または: uv sync --extra csp-ml

orb-models と PyTorch、NVIDIA Warp が入り（約 1 GB、いずれも Apache 2.0 ライセンス）、
Python 3.12 以上が必要です。GFN2-xTB だけを使う場合は不要です。

実行の流れ
----------

.. code-block:: bash

   molecular-modeling-csp input/csp.toml     # 予測（設定ファイルを省略すると input/csp.toml）
   python -m molecular_modeling.csp.validate csp_out exp1.cif exp2.cif   # 答え合わせ

``exp1.cif`` と ``exp2.cif`` は、ご自身で用意する実験の CIF ファイルを表します（リポジトリには含まれません）。
相対パス（設定ファイル、その中の ``molecule``・``cif``・``out_dir``）は、設定ファイルのあるディレクトリではなく
現在のディレクトリを基準に解釈されます。どちらのコマンドも 1 プロセスで実行してください。``mpiexec`` で
2 プロセス以上にするとエラーで止まります（緩和の並列化には ``n_procs`` を使います）。入力に誤りがある（設定の誤り、ファイルがない・読めない、
パッケージが足りない、緩和の計算方法が動かない）と、``error: <メッセージ>`` を出して終了コード 2 で止まります。

予測は次の順に進みます。

1. **候補生成**: 空間群ごとに PyXtal で結晶を作ります（ランダム）。
   一部は分子の向きを Voronoi セルで決め直します（Voronoi 生成器）。
   置換元 CIF を与えたときは、そこからも作ります（seed 生成器）。
2. **重なりチェックと事前ふるい**: 原子が近すぎる候補、分子が切れた候補、
   充填率が範囲外の候補を捨て、残りを剛体分子の簡易な分子間エネルギー（UFF の LJ）で並べて
   上位 ``n_prescreen_keep`` 件に絞ります。
3. **緩和**: ``relax_method`` で選んだ方法（既定は GFN2-xTB）で、原子と格子を動かして緩和します
   （複数プロセスで並列）。
   分子が入力から大きく変形した候補は捨てます。
4. **重複除去と順位付け**: 同じ構造をまとめ、1 分子あたりのエネルギーで並べます。
5. **出力**: 順位表と上位 50 件の CIF を書き出します。

分子の座標は拡大・縮小しません。分子に許される操作は剛体としての回転と平行移動だけで、
例外は緩和です。

入力ファイル（input/csp.toml）
------------------------------

.. list-table::
   :header-rows: 1
   :widths: 22 20 58

   * - キー
     - 既定値
     - 意味
   * - ``molecule``
     - （必須）
     - 分子ファイル。``data/<name>.toml`` または ``.xyz``。孤立分子の直交座標で、
       結合でつながった 1 分子であること（切れていると読み込みでエラー）
   * - ``mode``
     - ``"blind"``
     - ``"blind"`` か ``"informed"``。下の「2 つのモード」を参照
   * - ``space_groups``
     - 6 個（下記）
     - 試す空間群の番号。``informed`` では必須。``blind`` では既定のリストに置き換わる
       （既定と違うリストが書いてあれば警告を出す）
   * - ``z``
     - 省略
     - 空間群ごとの Z（例: ``z = { 14 = 4 }``）。省略時は一般位置の多重度 × ``z_prime``。
       ``blind`` では無視される
   * - ``z_prime``
     - ``1``
     - 非対称単位あたりの分子数。``blind`` では 1 に固定（ほかの値なら警告を出して 1 にする）。
       Z' = 2 の結晶は ``informed`` で指定する（計算量が増える）
   * - ``n_candidates_per_sg``
     - ``150``
     - 空間群ごとに作る候補の数（ランダム + Voronoi）。これは上限で、PyXtal は要求数の 5 倍の試行で
       あきらめ、分子が切れてしまう Voronoi の向きは捨てるため、少なくなることがある。
       足りなかったときは ``run.log`` に出る
   * - ``generators``
     - ``{random=0.6, voronoi=0.4}``
     - 生成器の割合（相対値。有限で 0 以上。名前は ``random``・``voronoi``・``seed``）。
       書いた表は既定値に上書きで重ねられ、書かなかった名前は既定の値のまま残る。
       そのため ``generators = {seed = 0}`` は置換元だけを止める。生成器を止めるには 0 を書く。
       ``random`` と ``voronoi`` はこの比で ``n_candidates_per_sg`` を分け合う。
       ``seed`` は使う／使わないの切り替えだけで、置換元を与えると既定で 0.5（使う）が加わる。正の値なら使い、
       ``seed = 0`` にすると置換元を使わない。置換元からは置換の選び方 1 通りにつき 1 件が必ず作られる。
       少なくとも 1 つの生成器が動いている必要がある
   * - ``seed_structures``
     - 省略
     - 置換元 CIF のリスト（``[[seed_structures]]``）。下記
   * - ``packing_range``
     - ``[0.4, 0.8]``
     - 生成直後（緩和前）の充填率の範囲。充填率 = 分子数 × 分子の vdW 体積 / セル体積
   * - ``overlap_factor``
     - ``0.7``
     - 異なる分子の原子どうし（分子とその分子自身の周期像の間も含む）の距離が
       「vdW 半径の和 × この値」より小さい候補を捨てる
   * - ``n_prescreen_keep``
     - ``32``
     - 事前ふるいのあと緩和する件数
   * - ``relax_method``
     - ``"GFN2-xTB"``
     - 緩和の計算方法: ``"GFN2-xTB"``、``"GFN1-xTB"``、``"OrbMol-v2"``\ （``csp-ml`` extra が必要）。
       下の「緩和の計算方法の選び方」を参照。コマンドの ``--relax-method`` で上書きできる
   * - ``relax_steps``
     - ``60``
     - 緩和 1 件あたりの最大ステップ数
   * - ``relax_fmax``
     - ``0.05``
     - 緩和の力の収束条件（eV/Å）
   * - ``n_procs``
     - CPU コア数
     - 並列プロセス数
   * - ``max_mol_rmsd``
     - ``0.5``
     - 緩和後に、分子が入力分子から（水素を除いて）この RMSD（Å）を超えて
       変形した候補を捨てる。分子内の結合が増えたり減ったりした候補（環が閉じた、
       水素が別の原子に移ったなど）は、RMSD にかかわらず捨てる
   * - ``time_budget_min``
     - ``60``
     - 時間の目安（分）。下の「時間の目安と既定値」を参照
   * - ``rng``
     - ``1``
     - 乱数シード。同じ値で同じ候補が出るのは、入力ファイル・設定・ソフトウェアの版
       （PyXtal、NumPy など）がすべて同じときに限る
   * - ``out_dir``
     - ``"csp_out"``
     - 出力先ディレクトリ

既定の空間群は ``[14, 2, 19, 15, 4, 61]``
（P2\ :sub:`1`/c、P-1、P2\ :sub:`1`\ 2\ :sub:`1`\ 2\ :sub:`1`、C2/c、P2\ :sub:`1`、Pbca）です。
設定ファイルに未知のキーがあるとエラーになります。値が範囲外のときもエラーです。
``packing_range`` は 0 < 下限 < 上限 ≤ 1、空間群（と ``z`` のキー）は 1〜230、
``n_candidates_per_sg``・``n_prescreen_keep``・``n_procs``・``z_prime`` と ``z`` の値は 1 以上、
``relax_steps`` は 0 以上、``relax_fmax``・``max_mol_rmsd``・``time_budget_min``・``overlap_factor`` は
正の値、``rng`` は 0 以上の整数でなければなりません。型の違う値（``space_groups = 14`` など）や、
``[[seed_structures]]`` の中の未知のキーも、キー名を示すエラーになります。重複した空間群は取り除き、
探さない空間群に対する ``z`` は無視します（どちらも警告を出します）。
設定ファイルを読むときに出た警告（``blind`` で無視されるキーなど）は、
画面に出るほか ``run.log`` の先頭にも書かれます。

最小の入力ファイル
~~~~~~~~~~~~~~~~~~

ブラインドで探すときは分子だけ指定すれば足ります（ほかのキーは既定値）。

.. code-block:: toml

   molecule = "data/benzene.toml"
   mode = "blind"

情報ありで探すときは、実験で分かっていることを与えます（この例では置換元 CIF も加えています）。

.. code-block:: toml

   molecule = "data/my_molecule.toml"
   mode = "informed"
   space_groups = [14]
   z = { 14 = 4 }
   z_prime = 1

   [[seed_structures]]
   cif = "parent.cif"
   substitutions = [["O", "S", 1]]

リポジトリの ``input/csp.toml`` は、すべてのキーにコメントを付けた例です。
組み込みの既定値ではなく、すぐ終わるように軽くしたベンゼンの例です
（``n_candidates_per_sg = 50``、既定は 150。``n_procs = 4``、既定は CPU コア数）。
``blind`` では無視されるので ``space_groups`` の行はコメントアウトしてあります。
使うときは ``mode = "informed"`` にしてからコメントを外してください。

分子ファイル ``data/<name>.toml`` の書式は、このツールのほかの部分で使う分子定義と同じです
（:doc:`toml_reference` の「分子定義」を参照）。リポジトリには ``data/benzene.toml`` と
``data/naphthalene.toml`` が入っています。CSP に必要なのは元素記号と直交座標（Å）だけで、
たとえば O=C=O 分子なら次のように書きます。

.. code-block:: toml

   symbols = ["O", "C", "O"]
   positions = [[-1.16, 0.0, 0.0],
                [ 0.00, 0.0, 0.0],
                [ 1.16, 0.0, 0.0]]

CSP が読むのは ``symbols`` と ``positions``、
それに ``use_fractional = true`` のとき座標の変換に使う ``lattice_vectors`` だけで、
``center_of_mass`` などほかのキーは使いません。分子 1 個の ``.xyz`` ファイル（フレームは 1 つだけ。``Properties=`` 行のある拡張 XYZ は、その列の定義に従って読みます）も使えます。
元素記号はふつうの大文字・小文字（``C``、``Cl``）で書き、0.5 Å より近い原子の組があってはいけません。
そうでなければ、ファイル名を示して読み込みが止まります。
分子は重心が原点に来るように平行移動されます。このガイドでいう重心は、質量で重み付けしない
原子座標の単純平均（幾何中心）です。

.. tip::

   分子ファイルは GUI で結晶構造から作れます。分子 1 個の原子を選び、
   **MoleculeTools** → **Save Selection as Molecule...** を選ぶと ``data/<name>.toml`` が書き出されます
   （:doc:`gui_guide` を参照）。セルの境界で切れた分子は、つなぎ直してから保存されます。
   選ぶのは、結合でつながった完全な分子 1 個です。そうでないとき（複数の分子、原子の欠け）は、
   ダイアログが警告を出し、保存してよいか確かめます。

**使える元素**: H、C、N、O、F、S、Cl、Se、Br、I。剛体 LJ の事前ふるいに UFF のパラメータがあるのは
これらだけで、ほかの元素を含む分子は、候補生成を始める前にエラーになります。

置換元 CIF（seed_structures）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: toml

   [[seed_structures]]
   cif = "parent.cif"
   substitutions = [["O", "S", 1]]   # (置換前の元素, 置換後の元素, 分子あたりの個数)
   volume_scale = "auto"             # 数値でも指定できる

置換元の CIF は **disorder を取り除いた（部分占有のない）もの** にしてください
（VESTA などで秩序化し、P1 で保存）。部分占有があるとエラーになります。

``volume_scale = "auto"`` は、置換元のセルをファンデルワールス体積の比（入力分子 ÷ 置換元の分子）で
等方的に拡大・縮小します（各辺の長さはその比の 3 乗根倍）。数値を書くと、その値を体積比として使います。
分子は重心の分率座標を保つように剛体のまま動かすだけで、分子自体は拡大・縮小しません。

置換元からの候補は ``n_candidates_per_sg`` とは別に作られます。置換元 1 つにつき、
置換の選び方 1 通りごとに 1 件（すべて P1）です。

2 つのモード
------------

``blind`` （ブラインド）
   予測したい結晶の情報を使いません。空間群は既定の 6 個、Z は一般位置の多重度、Z' = 1 です。
   設定ファイルの ``space_groups`` と ``z`` は無視し、``z_prime`` は 1 にします
   （どれも、ほかの値が書いてあれば警告を出します）。``seed_structures`` を与えた場合は使います。
   置換元は関連する別の結晶（O→S 置換の前の母化合物など）で、予測したい結晶の実験構造ではないためです。
   分子だけから予測したいときは ``seed_structures`` を書かないか、
   ``generators = {seed = 0}`` として置換元を止めてください（ほかの重みは既定値のまま）。

``informed`` （情報あり）
   実験で分かっている空間群（必須）、``z``、``z_prime`` を指定します。答えに近い領域を重点的に探すモードです。
   ``seed_structures`` は ``blind`` と同じように加えられます。

Voronoi の使い方
----------------

以前の Voronoi パイプライン（``run.py``）は、置換元の重心配置から作った Voronoi セルとの
IoU を最大にしていました。CSP では **向きの初期値** を決めるために使い方を変えています。

- PyXtal が作った結晶の分子重心から、各分子の Voronoi セルを作る。
- **分子そのものの形**\ （原子を vdW 半径でふくらませた凸包）と、そのセルの IoU が最大になる向きを探す。
  比較のときだけ、形をセルの体積に合わせて拡大・縮小する。原子座標は拡大・縮小せず、剛体として回転させるだけ。
- 形からは頭と尻尾が区別できないので、骨格ごとに、最良の向きと、それを重心を通り
  分子面に垂直な軸のまわりに 180° 回した向きの 2 通りを候補にする。この回転で分子の両端
  （OS-2SMe なら O の端と S の端）が入れ替わり、分子面は保たれる。回転してもすべての分子が自分自身に
  重なる場合（同じ元素の原子が 0.1 Å 以内。ベンゼンやナフタレンなど）は、回した向きは重複になるので作らない。
  そのぶん骨格を多く使い、``n_candidates_per_sg`` のうち Voronoi の割り当て分は埋める。
  ``candidates.csv`` ではどちらも由来 ``voronoi`` になる。
- 空間群の対称性は保つ（向きを決めるのは非対称単位の分子で、残りは空間群の操作で作る）。

どの候補にも、生成器が ``candidates.csv`` の ``origin`` 列に記録されます
（``random``、``voronoi``、``seed:<名前>``）。答え合わせの結果 ``validation.md`` にも、
一致した候補と近い候補それぞれの ``origin`` が載るので、どの生成器が実験構造に近い構造を作ったかが分かります。

出力の読み方
------------

``csp_out/`` に次のファイルができます。

``candidates.csv``
   順位表。エネルギーの低い順です。

   .. list-table::
      :header-rows: 1
      :widths: 28 72

      * - 列
        - 意味
      * - ``rank``
        - 順位（1 が最安定）
      * - ``id``
        - 候補の識別子 ``<由来>-<空間群>-<通し番号>``。由来の ``:`` と ``/`` は ``_`` に置き換える。
          例: ``random-14-3``、``voronoi-2-17``、``seed_parent-1-0``
      * - ``energy_per_mol_eV``
        - 緩和の計算方法による 1 分子あたりのエネルギー（eV）。エネルギーの基準は方法ごとに違うので、
          比べてよいのは同じ方法の行どうしだけ
      * - ``rel_energy_kJmol``
        - 1 位との差（kJ/mol、1 分子あたり）
      * - ``density_gcm3``
        - 緩和後の密度（g/cm³）
      * - ``space_group_in``
        - 生成時に指定した空間群
      * - ``space_group_out``
        - 緩和後に spglib で判定し直した空間群（0 は判定失敗）
      * - ``origin``
        - 由来: ``random``、``voronoi``、``seed:<名前>``\ （``<名前>`` は置換元 CIF のファイル名から
          拡張子を除いたもの。例: ``seed:parent``）
      * - ``max_mol_rmsd``
        - 緩和後の分子の変形（水素を除く RMSD、Å）
      * - ``status``
        - ``relaxed``: 緩和後のチェック（変形・結合）を通った候補。緩和が ``relax_fmax`` まで
          収束したという意味ではなく、``relax_steps`` で打ち切られた場合もある
      * - ``relax_method``
        - その実行で使った緩和の計算方法（``GFN2-xTB``、``GFN1-xTB``、``OrbMol-v2``）

``001_<id>.cif`` … ``050_<id>.cif``
   上位 50 件の構造。答え合わせでは ``candidates.csv`` に載っている CIF だけを読みます。

``out_dir`` を使い回すとき
   設定・分子・置換元 CIF を最初に確かめ、どれかに誤りがあれば ``out_dir`` に触れずに止まるので、
   前の実行の結果はそのまま残ります。実行が始まると、前の ``candidates.csv``・順位付き CIF
   （``NNN_<id>.cif``）・``validation.md`` を消し、``run.log`` を上書きします。新しい結果は最後に
   書き出し、``candidates.csv`` が最後です。エラーや中断（Ctrl-C）で止まった場合は、理由を
   ``run.log`` に書き、結果は何も残さないので、前の実行の結果を新しい結果と取り違えることはありません。
   結果を入れ替えている間、ディレクトリには目印のファイル ``.csp_incomplete`` があります。古い結果を消す前に
   作り、新しい ``candidates.csv`` を置いたあとで最後に消します。エラー・中断・強制終了で止まった実行は
   目印を残すので、次の実行が最後まで終わるまで、答え合わせはそのディレクトリを断ります。
   同じ ``out_dir`` で 2 つの実行を同時に動かさないでください。実行中はロックファイル ``.csp_run.lock``
   があり、答え合わせも結果を読んで ``validation.md`` を書くまで同じロックを持つので、同じディレクトリの
   実行と答え合わせが重なることはなく、あとから来たほうは断られます。実行を強制終了してロックファイルが
   残った場合は、ロックファイルを消して **実行し直してください**\ 。目印があるので、途中までの結果が
   答え合わせに使われることはありません。そのため答え合わせには ``out_dir`` への書き込み権限が必要です。
   ロックファイルを作れない場合（読み取り専用の結果のコピーなど）は、ロックなしで読むのではなくエラーで
   止まります。先に書き込みできる場所へディレクトリをコピーしてください。

``run.log``
   各段で何件残ったかと所要時間。次の入力で実際に実行した例です（ほかのキーは既定値:
   ``generators = {random = 0.6, voronoi = 0.4}``、``packing_range = [0.4, 0.8]``、``overlap_factor = 0.7``）。

   .. code-block:: toml

      molecule = "data/benzene.toml"
      mode = "informed"
      space_groups = [2, 14]          # P-1（Z = 2）と P2_1/c（Z = 4）
      n_candidates_per_sg = 100
      n_prescreen_keep = 150
      relax_steps = 60
      n_procs = 2
      time_budget_min = 3
      rng = 1

   ログ（空間群ごとの行は省略）::

      generated 200 candidates {'random': 120, 'voronoi': 80} in 49.5 s
      prescreen {'generated': 200, 'no_overlap': 86, 'packing': 86, 'kept': 86} in 3.8 s
      time budget: 43.6 s per candidate, 21 s left; relaxing 0 of 84 remaining candidates
      relax: 2 relaxed, 0 rejected_deformed, 0 failed in 87.3 s
      dedupe: 2 -> 2 in 0.0 s

   件数は入力から次のように決まります。2 空間群 × 100 件 = 200 件で、空間群ごとにランダム 60 件と
   Voronoi 40 件。ベンゼンは 180° 回しても変わらないので、Voronoi の 40 件はそれぞれ別の PyXtal の骨格から
   作られます。重なりのない 86 件はすべて充填率の範囲内で、``n_prescreen_keep = 150`` のほうが多いので
   86 件とも残ります。最初の 1 周（``n_procs`` = 2 件、87 秒）で 3 分の目安のほとんどを使ったため、
   残りの 84 件は緩和していません。生成の 50 秒は、ほとんどが Voronoi の向き探索の時間です。
   緩和の件数は最初の 1 周にかかった時間で決まるので、この時間を測った実行での観測結果であり、
   いつも同じになるとは限りません。所要時間は実行ごとに数秒ずれます。このログは
   Python 3.13.12、pyxtal 1.1.5、tblite 0.8.0、ase 3.29.0、numpy 2.5.4、scipy 1.18.1、
   pymatgen 2026.10.24、spglib 2.8.0 で、同じ件数になることを確かめています。

   ``rejected_deformed`` は、緩和中に分子が ``max_mol_rmsd`` を超えて変形したか、分子内の結合が
   増えたり減ったりしたか、ほかの分子や自分自身の周期像と共有結合でつながってしまった件数、
   ``failed`` は計算がエラーで止まった件数です。tblite が入っていない場合は、ここで全件が失敗するのではなく、
   候補生成の前に実行が止まります（`インストール`_ を参照）。
   ``relax:`` の行のあとには、理由ごとに失敗・除外した件数と最初のメッセージが 1 行ずつ出ます
   （例: ``2 failed: InputError: Too close interatomic distances``）。
   ``time budget: ...`` という行があれば、時間の目安に収めるため緩和する件数を減らしたことを表します。

答え合わせ
----------

.. code-block:: bash

   python -m molecular_modeling.csp.validate csp_out exp_OS-i.cif exp_OS-ii.cif
   # 任意: --n-top 20  --rmsd-cut 0.8  --flip O,S  （--no-flip で flip 判定を省く）

結果は画面と ``csp_out/validation.md`` に出ます。実験 CIF は **disorder のないもの**、
つまりどのサイトも 1 つの元素で占有率がちょうど 1 のものにしてください。disorder のある構造は、
主成分だけを残して秩序化した P1 の CIF として保存してください。
実験 CIF によくある、水素原子のない CIF でもかまいません。比べるのは重原子だけなので、
水素の有無にかかわらず同じ候補と一致します。出力ディレクトリがない、``candidates.csv`` も
候補の CIF もない、実行中である、または最後まで終わらなかった実行の結果である
（「``out_dir`` を使い回すとき」を参照）場合は、報告を書かずにエラーで止まります。読めない実験 CIF も同じです。
報告では実験構造をファイル名で示し、同じ名前のファイルが 2 つあるときは与えたパスで示します。

flip 判定（``--flip O,S``）は **既定で有効** です。O や S を含まない分子では判定することがなく、
skipped と報告されます。省くには ``--no-flip`` を、別の 2 元素で判定するには ``--flip`` に
異なる 2 つの元素を与えてください（例: ``--flip Se,S``。大文字・小文字は問いません）。
``--flip`` と ``--no-flip`` は同時に使えず、``--n-top`` は 1 以上、``--rmsd-cut`` は正の値です。

比べ方は COMPACK 方式です。実験構造と候補から 15 分子のクラスターを取り、重ねたときの RMSD\ :sub:`15`
を求めます。RMSD\ :sub:`15` は重原子で計算します（水素を除く。重原子のない分子では全原子）。
RMSD\ :sub:`15` < 0.8 Å で、15 分子すべてが対応づいたものを「一致」とします。
比較はどちらの構造を基準にしても行い、悪いほうの結果を採るので、どちらかに余分な分子や欠けた分子があれば
一致になりません。分子の数密度（体積あたりの分子数）が 1.2 倍を超えて違う構造は「比較できない」とします
（同じ多形なら緩和後でも差は数 % です）。

報告には次の項目が出ます（``validation.md`` での表記のまま載せています）。

``success``
   一致する候補が上位 ``n_top``\ （既定 20）件以内にあれば yes。
``best match rank``
   比較した CIF のうち、一致した候補の最上位の順位。``n_top`` より下でも載るので、
   「生成はできたが順位が低かった」ことが分かります。比較するのは書き出した CIF（重複除去後の上位 50 件）
   だけなので、一致がなくても **生成できなかったとは限りません**。50 位より下だった、事前ふるい・
   時間の目安・変形チェックで落ちた、という場合もあります。
``mirror``
   鏡像を重ねて一致したか。
``flip match rank``
   O と S を同じ元素とみなしたときにだけ一致する候補（以下「反転一致」、flip match）の最上位順位。
   **充填は同じで、分子の O と S が入れ替わった構造** を意味します。成功とは数えません。
   実験構造に 2 つの元素のどちらかがない場合は、たとえば
   ``skipped (no O, S in the experimental structure)``\ （両方ない）や
   ``skipped (no S in the experimental structure)`` と表示されます。
``closest candidates``
   実験構造ごとに必ず出ます。比較できた候補を、対応づいた分子数の多い順、次に RMSD、次に順位で並べた
   最大 10 件です。
``Not comparable``
   比較できなかった候補とその理由です。理由の例: クラスターの分子の組成が異なる、
   分子の数密度が違いすぎる、比べる分子がない、候補 CIF を読めない・見つからない。

緩和の計算方法の選び方
----------------------

``relax_method``\ （コマンドの ``--relax-method`` を付けるとそちらが優先）で、候補の緩和と順位付けに
使う方法を選びます。

``GFN2-xTB``\ （既定）、``GFN1-xTB``
   tblite による強束縛法です。``csp`` extra に含まれます。
``OrbMol-v2``
   機械学習の原子間ポテンシャルです（orb-models。学習データ OMol25 は、CSP が扱う元素を Se も含めて
   すべて含みます）。``csp-ml`` extra が必要です。分子は中性・一重項として扱います。

小さな比較試験（2026-11-06。ナフタレンと Se を含む 2 つの化合物で、それぞれ実験構造と PyXtal の
ランダム候補 6〜12 個を最大 300 ステップ緩和）では、OrbMol-v2 は 3 系とも実験構造を最も低く並べ、
候補 1 個あたりの時間は GFN2-xTB の約半分でした。GFN2-xTB はナフタレンでランダム候補 1 個を
実験構造より 20 kJ/mol 低く並べ、ジフェニルジセレニドの実験構造では SCF が収束せず失敗しました。
**Se を含む分子や、GFN2-xTB の順位が当てにならないときは、OrbMol-v2 を試す価値があります。**
ただしこの試験は系も候補も少なく、候補は本パイプラインのものより密度が低く、DFT との照合もしていません。
既定値は GFN2-xTB のままです。

エネルギーの基準は方法ごとに違います。``energy_per_mol_eV`` や順位を比べてよいのは、同じ方法の中だけです。
どの方法を使ったかは、``candidates.csv`` の ``relax_method`` 列と ``run.log`` の最初の方に記録されます
（``run.log`` には、設定の出どころ ``default``・``config``・``cli``・``argument``、パッケージのバージョン、
OrbMol-v2 では重みのファイル名も書きます）。

**重みとネットワーク。** OrbMol-v2 は初めて使うときに重み（約 100 MB）を ``~/.cache/cached_path``\
（``CACHED_PATH_CACHE_ROOT`` を設定していればそのディレクトリ）に取得します。OrbMol-v2 の実行では、
``out_dir`` に触る前に、別プロセスでモデルを作って水 1 分子を計算する動作確認をします（最長 10 分）。
ネットにつながらない計算機などでこれが失敗すると、原因とキャッシュの場所を書いた 1 行の ``error:`` で
止まります。そのような計算機を準備するには、ネットにつながる計算機で次を実行し、キャッシュの
ディレクトリをまるごとコピーしてください。

.. code-block:: bash

   python -c "from orb_models.forcefield import pretrained; pretrained.orbmol_v2(device='cpu')"

各ワーカープロセスは、最初の周の前にモデルを 1 回だけ読み込みます。この時間は ``time_budget_min`` には
数えますが、1 周の時間には入れません。緩和の設定（``relax_steps``、``relax_fmax``）と事前ふるいは、
どの方法でも共通です。下の時間の目安は GFN2-xTB で測ったものです。OrbMol-v2 は、本パイプラインの条件
（ワーカー 1 つあたり 1 スレッド）ではまだ測っていません。

時間の目安と既定値
------------------

Apple Silicon の Mac（8 コア）で実測しました。分子は OS-2SMe の代わりに
ナフタレン（18 原子、重原子 10 個）を使い、空間群 P2\ :sub:`1`/c（Z = 4、72 原子）で測っています。
OS-2SMe は重原子がやや多いので、これより重くなる見込みです。

.. list-table::
   :header-rows: 1
   :widths: 60 40

   * - 項目
     - 実測
   * - PyXtal の生成（1 件）
     - 約 0.04 秒
   * - 剛体 LJ エネルギー（1 件）
     - 約 0.08 秒
   * - Voronoi による向き決め（骨格 1 件、2 候補が出る）
     - 約 0.7 秒
   * - GFN2-xTB の緩和 1 ステップ（1 プロセスだけ動かしたとき）
     - 約 4.5 秒
   * - 同 8 プロセス同時のとき
     - 約 10.9 秒（1 件あたりの実効 1.4 秒）
   * - （参考）ベンゼン P-1 Z = 2（24 原子）、150 ステップ
     - 約 17 秒

GFN2-xTB のコストは原子数の 3 乗（27 倍）より急に増え、今回の実測では 72 原子は 24 原子の約 40 倍
（1 ステップあたり）でした。
緩和が時間のほとんどを占めます。

**既定値の根拠**\ （``time_budget_min = 60`` の 90 % = 54 分以内に収める）。
この計算は、要求した候補がすべて生成できたと仮定しています。生成数が足りない場合
（``n_candidates_per_sg`` を参照）は、事前ふるいにかける候補が減りますが、実行時間が短くなるとは
限りません。PyXtal は要求数の 5 倍の試行まで作り直すので生成がかえって長くなることがあり、
事前ふるいを通る候補が ``n_prescreen_keep`` 件以上あれば緩和の時間は変わらないためです:

- 生成と事前ふるい: 6 空間群 × 150 件 = 900 件。1 空間群あたりランダム 90 件と Voronoi 60 件です。
  ナフタレンは 180° 回しても同じ向きになるので、PyXtal の骨格 1 個から Voronoi の候補は 1 件で、
  骨格は 60 個必要です（OS-2SMe のように両端が違う分子なら骨格 1 個から 2 件で、30 個）。
  PyXtal で作る結晶は 6 × (90 + 60) = 900 個（約 36 秒）、Voronoi の向き決めは 6 × 60 骨格 × 0.7 秒
  （約 4 分）、LJ 順位付けは約 20 秒で、計 約 5〜6 分。置換元からの候補はこれとは別に加わります。
- 緩和 1 周（8 件を同時）: 60 ステップ × 10.9 秒 ≈ 11 分。
- 残り 54 − 6 = 48 分で 4 周 ≈ 44 分、つまり 8 × 4 = **32 件**\ （``n_prescreen_keep = 32``）。
- 合計で約 50 分、時間の目安に収まります。**この合計は実測したステップ時間からの計算値で、既定値の実行を
  最後まで通して測ったものではありません。** 60 ステップでの収束は確認しておらず、
  ``relax_fmax`` に届かない場合があります。
- ナフタレンより大きい分子（OS-2SMe など）は 1 ステップが遅いため、同じ時間で回せる周数が減ります。

``relax_steps`` を 150 に増やすと 1 周が約 27 分になり、1 時間では 1 周（8 件）しか回せません。
緩和は収束しきらなくても、順位付けの前に候補を絞るには足りるという判断で 60 にしています。
本番では ``time_budget_min`` を長くする、空間群を減らす（``informed``）、
``n_procs`` を CPU コア数にあわせる、のいずれかで件数を増やしてください。

時間の目安の仕組みは次のとおりです。候補は ``n_procs`` 件ずつの周に分けて緩和し、1 周ごとに時間を測ります。
次の周に入る前に、残り時間（``time_budget_min`` の 90 % からそれまでの経過時間を引いたもの）を
それまでで最も遅かった周の時間と比べ、足りなければ残りの候補は緩和しません。
周ごとに確かめるので、2 周目以降が最初の周より遅くなっても早めに止まります。ただし、思いがけず遅い 1 周が
あると、その周の長さの分までは目安を超えることがあります。
**最初の 1 周は必ず実行する**\ （既定値のナフタレンで約 11 分、生成に約 6 分）ので、
``time_budget_min`` が約 17 分未満だと目安を超えます。

充填率の範囲について
~~~~~~~~~~~~~~~~~~~~

PyXtal が作る緩和前のセルは、実際の結晶（充填率 0.6〜0.8 程度）よりかなり疎で、
ベンゼンで約 0.46、ナフタレンで約 0.52 でした（どの空間群・どの乱数でもほぼ同じ値）。
そのため ``packing_range`` の既定は ``[0.4, 0.8]`` にしています。
PyXtal の体積係数 ``factor`` を 1.1 から 0.8 に下げて密にすることもできますが、
密にした分、重なりチェックで落ちる候補が増えます（ナフタレンで、重なりのない候補が
``factor = 1.1`` で約 2 割から、0.8 ではほぼ 0 になる）。このため既定の体積係数を採用し、範囲のほうを広げました。

制限事項
--------

- **分子は入力の配座で剛体です。** 配座の自由度（ねじれ）は生成の段階では振りません。
  緩和で多少は動きますが、``max_mol_rmsd`` を超えると捨てられます。
- **エネルギーの順位（GFN2-xTB でも OrbMol-v2 でも）では、近い多形を分けられないことがあります。** 特に双極子をもつ分子では、
  エネルギー差が方法の誤差より小さくなります。実験構造が生成できていても、順位が ``n_top`` より下
  （50 位より下なら比較の対象にもならない）になることがあります。
- **flip disorder は扱いません。** O と S が入れ替わった分子の混在（占有率が 1 でないサイト）は
  再現せず、「反転一致」（flip match）として別に報告するだけです。
- 置換元 CIF と実験 CIF は **disorder のない** ものが必要です。
- 緩和は力の収束まで行わないことがあり（``relax_steps`` で打ち切り）、エネルギーはその状態のものです。
- DFT による再評価や、スーパーコンピュータでの大規模な探索は含みません。
