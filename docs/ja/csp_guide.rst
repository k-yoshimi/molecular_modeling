結晶構造予測（CSP）ガイド
=========================

分子の構造（孤立分子の座標）だけから、分子結晶の候補構造を作り、
GFN2-xTB で緩和してエネルギー順に並べ、実験の CIF と答え合わせをするための手順書です。
OS-2SMe のように、O と S の入れ替わり（flip）がある分子結晶を想定していますが、
一般の有機分子結晶にも使えます。

.. contents:: 目次
   :local:
   :depth: 2

インストール
------------

このガイドのコマンドは、すべてリポジトリの最上位（``pyproject.toml`` のあるディレクトリ）で実行します。
Python 3.11 以上が必要です。

.. code-block:: bash

   python -m venv .venv          # 仮想環境がまだなければ最初に 1 回
   source .venv/bin/activate
   pip install -e ".[csp]"

``csp`` extra で PyXtal、tblite（GFN2-xTB）、pymatgen が入ります。
本体の依存ライブラリには含まれません。

実行の流れ
----------

.. code-block:: bash

   molecular-modeling-csp input/csp.toml     # 予測（設定ファイルを省略すると input/csp.toml）
   python -m molecular_modeling.csp.validate csp_out exp1.cif exp2.cif   # 答え合わせ

``exp1.cif`` と ``exp2.cif`` は、ご自身で用意する実験の CIF ファイルを表します（リポジトリには含まれません）。

予測は次の順に進みます。

1. **候補生成**: 空間群ごとに PyXtal で結晶を作ります（ランダム）。
   一部は分子の向きを Voronoi セルで決め直します（Voronoi 生成器）。
   置換元 CIF を与えたときは、そこからも作ります（seed 生成器）。
2. **重なりチェックと事前ふるい**: 原子が近すぎる候補、分子が切れた候補、
   充填率が範囲外の候補を捨て、残りを剛体分子の簡易な分子間エネルギー（UFF の LJ）で並べて
   上位 ``n_prescreen_keep`` 件に絞ります。
3. **GFN2-xTB による緩和**: 原子と格子を動かして緩和します（複数プロセスで並列）。
   分子が入力から大きく変形した候補は捨てます。
4. **重複除去と順位付け**: 同じ構造をまとめ、1 分子あたりのエネルギーで並べます。
5. **出力**: 順位表と上位 50 件の CIF を書き出します。

分子の座標は拡大・縮小しません。分子に許される操作は剛体としての回転と平行移動だけで、
例外は GFN2-xTB による緩和です。

入力ファイル（input/csp.toml）
------------------------------

.. list-table::
   :header-rows: 1
   :widths: 22 20 58

   * - キー
     - 既定値
     - 意味
   * - ``molecule``
     - （必須）
     - 分子ファイル。``data/<name>.toml`` または ``.xyz``。孤立分子の直交座標で、
       結合でつながった 1 分子であること（切れていると読み込みでエラー）
   * - ``mode``
     - ``"blind"``
     - ``"blind"`` か ``"informed"``。下の「2 つのモード」を参照
   * - ``space_groups``
     - 6 個（下記）
     - 試す空間群の番号。``informed`` では必須。``blind`` では既定のリストに置き換わる
   * - ``z``
     - 省略
     - 空間群ごとの Z（例: ``z = { 14 = 4 }``）。省略時は一般位置の多重度 × ``z_prime``。
       ``blind`` では無視される
   * - ``z_prime``
     - ``1``
     - 非対称単位あたりの分子数。``blind`` では 1 に固定（ほかの値なら警告を出して 1 にする）。
       Z' = 2 の結晶は ``informed`` で指定する（計算量が増える）
   * - ``n_candidates_per_sg``
     - ``150``
     - 空間群ごとに作る候補の数
   * - ``generators``
     - ``{random=0.6, voronoi=0.4}``
     - 生成器の割合（相対値。有限で 0 以上。名前は ``random``・``voronoi``・``seed``）。
       書いた表は既定値に上書きで重ねられ、書かなかった名前は既定の値のまま残る。
       そのため ``generators = {seed = 0}`` は置換元だけを止める。生成器を止めるには 0 を書く。
       ``random`` と ``voronoi`` はこの比で ``n_candidates_per_sg`` を分け合う。
       ``seed`` は使う／使わないの切り替えだけで、置換元を与えると既定で 0.5（使う）が加わり、
       ``seed = 0`` にすると置換元を使わない。置換元からは置換の選び方 1 通りにつき 1 件が必ず作られる。
       少なくとも 1 つの生成器が動いている必要がある
   * - ``seed_structures``
     - 省略
     - 置換元 CIF のリスト（``[[seed_structures]]``）。下記
   * - ``packing_range``
     - ``[0.4, 0.8]``
     - 生成直後（緩和前）の充填率の範囲。充填率 = 分子数 × 分子の vdW 体積 / セル体積
   * - ``overlap_factor``
     - ``0.7``
     - 分子間の原子間距離が「vdW 半径の和 × この値」より小さい候補を捨てる
   * - ``n_prescreen_keep``
     - ``32``
     - 事前ふるいのあと GFN2-xTB で緩和する件数
   * - ``relax_steps``
     - ``60``
     - 緩和 1 件あたりの最大ステップ数
   * - ``relax_fmax``
     - ``0.05``
     - 緩和の力の収束条件（eV/Å）
   * - ``n_procs``
     - CPU コア数
     - 並列プロセス数
   * - ``max_mol_rmsd``
     - ``0.5``
     - 緩和後に、分子が入力分子から（水素を除いて）この RMSD（Å）を超えて
       変形した候補を捨てる
   * - ``time_budget_min``
     - ``60``
     - 時間の目安（分）。下の「時間の目安と既定値」を参照
   * - ``rng``
     - ``1``
     - 乱数シード（同じ値なら同じ候補が出る）
   * - ``out_dir``
     - ``"csp_out"``
     - 出力先ディレクトリ

既定の空間群は ``[14, 2, 19, 15, 4, 61]``
（P2\ :sub:`1`/c、P-1、P2\ :sub:`1`\ 2\ :sub:`1`\ 2\ :sub:`1`、C2/c、P2\ :sub:`1`、Pbca）です。
設定ファイルに未知のキーがあるとエラーになります。

最小の入力ファイル
~~~~~~~~~~~~~~~~~~

ブラインドで探すときは分子だけ指定すれば足ります（ほかのキーは既定値）。

.. code-block:: toml

   molecule = "data/benzene.toml"
   mode = "blind"

情報ありで探すときは、実験で分かっていることを与えます（この例では置換元 CIF も加えています）。

.. code-block:: toml

   molecule = "data/my_molecule.toml"
   mode = "informed"
   space_groups = [14]
   z = { 14 = 4 }
   z_prime = 1

   [[seed_structures]]
   cif = "parent.cif"
   substitutions = [["O", "S", 1]]

リポジトリの ``input/csp.toml`` は、すべてのキーにコメントを付けた例です。

分子ファイル ``data/<name>.toml`` の書式は、このツールのほかの部分で使う分子定義と同じです
（:doc:`toml_reference` の「分子定義」を参照）。リポジトリには ``data/benzene.toml`` と
``data/naphthalene.toml`` が入っています。CSP に必要なのは元素記号と直交座標（Å）だけで、
たとえば O=C=O 分子なら次のように書きます。

.. code-block:: toml

   symbols = ["O", "C", "O"]
   positions = [[-1.16, 0.0, 0.0],
                [ 0.00, 0.0, 0.0],
                [ 1.16, 0.0, 0.0]]

CSP が読むのは ``symbols`` と ``positions``、
それに ``use_fractional = true`` のとき座標の変換に使う ``lattice_vectors`` だけで、
``center_of_mass`` などほかのキーは使いません。分子 1 個の ``.xyz`` ファイルも使えます。
分子は単純平均の重心（質量で重み付けしない）が原点に来るように平行移動されます。

**使える元素**: H、C、N、O、F、S、Cl、Se、Br、I。剛体 LJ の事前ふるいに UFF のパラメータがあるのは
これらだけで、ほかの元素を含む分子は、候補生成を始める前にエラーになります。

置換元 CIF（seed_structures）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: toml

   [[seed_structures]]
   cif = "parent.cif"
   substitutions = [["O", "S", 1]]   # (置換前の元素, 置換後の元素, 分子あたりの個数)
   volume_scale = "auto"             # 数値でも指定できる

置換元の CIF は **disorder を取り除いた（部分占有のない）もの** にしてください
（VESTA などで秩序化し、P1 で保存）。部分占有があるとエラーになります。

``volume_scale = "auto"`` は、置換元のセルをファンデルワールス体積の比（入力分子 ÷ 置換元の分子）で
等方的に拡大・縮小します（各辺の長さはその比の 3 乗根倍）。数値を書くと、その値を体積比として使います。
分子は重心の分率座標を保つように剛体のまま動かすだけで、分子自体は拡大・縮小しません。

置換元からの候補は ``n_candidates_per_sg`` とは別に作られます。置換元 1 つにつき、
置換の選び方 1 通りごとに 1 件（すべて P1）です。

2 つのモード
------------

``blind`` （ブラインド）
   予測したい結晶の情報を使いません。空間群は既定の 6 個、Z は一般位置の多重度、Z' = 1 です。
   設定ファイルの ``space_groups`` と ``z`` は無視し、``z_prime`` は 1 にします
   （ほかの値が書いてあれば警告を出します）。``seed_structures`` を与えた場合は使います。
   置換元は関連する別の結晶（O→S 置換の前の母化合物など）で、予測したい結晶の実験構造ではないためです。
   分子だけから予測したいときは ``seed_structures`` を書かないか、
   ``generators = {random = 0.6, voronoi = 0.4, seed = 0}`` として置換元を止めてください。

``informed`` （情報あり）
   実験で分かっている空間群（必須）、``z``、``z_prime`` を指定します。答えに近い領域を重点的に探すモードです。
   ``seed_structures`` は ``blind`` と同じように加えられます。

Voronoi の使い方
----------------

以前の Voronoi パイプライン（``run.py``）は、置換元の重心配置から作った Voronoi セルとの
IoU を最大にしていました。CSP では **向きの初期値** を決めるために使い方を変えています。

- PyXtal が作った結晶の分子重心から、各分子の Voronoi セルを作る。
- **分子そのものの形**\ （原子を vdW 半径でふくらませた凸包）と、そのセルの IoU が最大になる向きを探す。
  比較のときだけ、形をセルの体積に合わせて拡大・縮小する。原子座標は拡大・縮小せず、剛体として回転させるだけ。
- 細長くほぼ対称な分子では形から頭と尻尾が区別できないので、最良の向きと、それを重心を通り
  分子面に垂直な軸のまわりに 180° 回した向きの 2 通りを候補にする。この回転で分子の両端
  （OS-2SMe なら O の端と S の端）が入れ替わり、分子面は保たれる。``candidates.csv`` ではどちらも
  由来 ``voronoi`` になる。
- 空間群の対称性は保つ（向きを決めるのは非対称単位の分子で、残りは空間群の操作で作る）。

どの候補にも、生成器が ``candidates.csv`` の ``origin`` 列に記録されます
（``random``、``voronoi``、``seed:<名前>``）。答え合わせの結果 ``validation.md`` にも、
一致した候補と近い候補それぞれの ``origin`` が載るので、どの生成器が実験構造に近い構造を作ったかが分かります。

出力の読み方
------------

``csp_out/`` に次のファイルができます。

``candidates.csv``
   順位表。エネルギーの低い順です。

   .. list-table::
      :header-rows: 1
      :widths: 28 72

      * - 列
        - 意味
      * - ``rank``
        - 順位（1 が最安定）
      * - ``id``
        - 候補の識別子 ``<由来>-<空間群>-<通し番号>``。由来の ``:`` と ``/`` は ``_`` に置き換える。
          例: ``random-14-3``、``voronoi-2-17``、``seed_parent-1-0``
      * - ``energy_per_mol_eV``
        - 1 分子あたりの GFN2-xTB エネルギー（eV）
      * - ``rel_energy_kJmol``
        - 1 位との差（kJ/mol、1 分子あたり）
      * - ``density_gcm3``
        - 緩和後の密度（g/cm³）
      * - ``space_group_in``
        - 生成時に指定した空間群
      * - ``space_group_out``
        - 緩和後に spglib で判定し直した空間群（0 は判定失敗）
      * - ``origin``
        - 由来: ``random``、``voronoi``、``seed:<名前>``\ （``<名前>`` は置換元 CIF のファイル名から
          拡張子を除いたもの。例: ``seed:parent``）
      * - ``max_mol_rmsd``
        - 緩和後の分子の変形（水素を除く RMSD、Å）
      * - ``status``
        - ``relaxed``\ （採用）

``001_<id>.cif`` … ``050_<id>.cif``
   上位 50 件の構造。同じ ``out_dir`` を使い回すと、前の実行の順位付き CIF（``NNN_<id>.cif``）は
   先に消されます。``candidates.csv`` と ``run.log`` は上書きされます。答え合わせでは
   ``candidates.csv`` に載っている CIF だけを読みます。

``run.log``
   各段で何件残ったかと所要時間。次の入力で実際に実行した例です（ほかのキーは既定値:
   ``generators = {random = 0.6, voronoi = 0.4}``、``packing_range = [0.4, 0.8]``、``overlap_factor = 0.7``）。

   .. code-block:: toml

      molecule = "data/benzene.toml"
      mode = "informed"
      space_groups = [2, 14]          # P-1（Z = 2）と P2_1/c（Z = 4）
      n_candidates_per_sg = 100
      n_prescreen_keep = 150
      relax_steps = 60
      n_procs = 2
      time_budget_min = 3
      rng = 1

   ログ（空間群ごとの行は省略）::

      generated 200 candidates {'random': 120, 'voronoi': 80} in 22.9 s
      prescreen {'generated': 200, 'no_overlap': 85, 'packing': 85, 'kept': 85} in 3.3 s
      time budget: 37.0 s per candidate, 62 s left; relaxing 0 of 83 remaining candidates
      relax: 2 relaxed, 0 rejected_deformed, 0 failed in 73.9 s
      dedupe: 2 -> 2 in 0.0 s

   件数は入力から次のように決まります。2 空間群 × 100 件 = 200 件で、空間群ごとにランダム 60 件と
   Voronoi 40 件。重なりのない 85 件はすべて充填率の範囲内で、``n_prescreen_keep = 150`` のほうが多いので
   85 件とも残ります。最初の 1 周（``n_procs`` = 2 件、74 秒）で 3 分の目安のほとんどを使ったため、
   残りの 83 件は緩和していません。生成の 23 秒は、ほとんどが Voronoi の向き探索の時間です。
   所要時間は実行ごとに数秒ずれます。

   ``rejected_deformed`` は、緩和中に分子が ``max_mol_rmsd`` を超えて変形したか、ほかの分子や
   自分自身の周期像と共有結合でつながってしまった件数、``failed`` は計算が失敗した件数です。
   ``time budget: ...`` という行があれば、時間の目安に収めるため緩和する件数を減らしたことを表します。

答え合わせ
----------

.. code-block:: bash

   python -m molecular_modeling.csp.validate csp_out exp_OS-i.cif exp_OS-ii.cif
   # 任意: --n-top 20  --rmsd-cut 0.8  --flip O,S  （--no-flip で flip 判定を省く）

結果は画面と ``csp_out/validation.md`` に出ます。実験 CIF は **disorder のない（全占有）もの** にしてください。

比べ方は COMPACK 方式です。実験構造と候補から 15 分子のクラスターを取り、重ねたときの RMSD\ :sub:`15`
を求めます。RMSD\ :sub:`15` は重原子で計算します（水素を除く。重原子のない分子では全原子）。
RMSD\ :sub:`15` < 0.8 Å で、15 分子すべてが対応づいたものを「一致」とします。
比較はどちらの構造を基準にしても行い、悪いほうの結果を採るので、どちらかに余分な分子や欠けた分子があれば
一致になりません。分子の数密度（体積あたりの分子数）が 1.2 倍を超えて違う構造は「比較できない」とします
（同じ多形なら緩和後でも差は数 % です）。

報告には次の項目が出ます（``validation.md`` での表記のまま載せています）。

``success``
   一致する候補が上位 ``n_top``\ （既定 20）件以内にあれば yes。
``best match rank``
   比較した CIF のうち、一致した候補の最上位の順位。``n_top`` より下でも載るので、
   「生成はできたが順位が低かった」ことが分かります。比較するのは書き出した CIF（重複除去後の上位 50 件）
   だけなので、一致がなくても **生成できなかったとは限りません**。50 位より下だった、事前ふるい・
   時間の目安・変形チェックで落ちた、という場合もあります。
``mirror``
   鏡像を重ねて一致したか。
``flip match rank``
   O と S を同じ元素とみなしたときにだけ一致する候補（以下「反転一致」、flip match）の最上位順位。
   **充填は同じで、分子の O と S が入れ替わった構造** を意味します。成功とは数えません。
   実験構造に O か S がない場合は ``skipped`` になります。
``closest candidates``
   実験構造ごとに必ず出ます。比較できた候補を、対応づいた分子数の多い順、次に RMSD、次に順位で並べた
   最大 10 件です。
``Not comparable``
   比較できなかった候補とその理由です。理由の例: クラスターの分子の組成が異なる、
   分子の数密度が違いすぎる、比べる分子がない、候補 CIF を読めない・見つからない。

時間の目安と既定値
------------------

Apple Silicon の Mac（8 コア）で実測しました。分子は OS-2SMe の代わりに
ナフタレン（18 原子、重原子 10 個）を使い、空間群 P2\ :sub:`1`/c（Z = 4、72 原子）で測っています。
OS-2SMe は重原子がやや多いので、これより重くなる見込みです。

.. list-table::
   :header-rows: 1
   :widths: 60 40

   * - 項目
     - 実測
   * - PyXtal の生成（1 件）
     - 約 0.04 秒
   * - 剛体 LJ エネルギー（1 件）
     - 約 0.08 秒
   * - Voronoi による向き決め（骨格 1 件、2 候補が出る）
     - 約 0.7 秒
   * - GFN2-xTB の緩和 1 ステップ（1 プロセスだけ動かしたとき）
     - 約 4.5 秒
   * - 同 8 プロセス同時のとき
     - 約 10.9 秒（1 件あたりの実効 1.4 秒）
   * - （参考）ベンゼン P-1 Z = 2（24 原子）、150 ステップ
     - 約 17 秒

GFN2-xTB のコストは原子数の 3 乗（27 倍）より急に増え、今回の実測では 72 原子は 24 原子の約 40 倍
（1 ステップあたり）でした。
緩和が時間のほとんどを占めます。

**既定値の根拠**\ （``time_budget_min = 60`` の 90 % = 54 分以内に収める）:

- 生成と事前ふるい: 6 空間群 × 150 件 = 900 件。1 空間群あたりランダム 90 件と Voronoi 60 件で、
  Voronoi の 60 件は PyXtal の骨格 30 個から、骨格ごとに 2 通りの向き（最良の向きと、それを分子面に垂直な軸のまわりに
  180° 回して頭と尻尾を入れ替えた向き）で作ります。PyXtal で作る結晶は 6 × (90 + 30) = 720 個（約 30 秒）、
  Voronoi の向き決めは 6 × 30 骨格 × 0.7 秒（約 2 分）、LJ 順位付けは約 20 秒で、計 約 3〜4 分。
  置換元からの候補はこれとは別に加わります。
- 緩和 1 周（8 件を同時）: 60 ステップ × 10.9 秒 ≈ 11 分。
- 残り 54 − 4 = 50 分で 4 周 ≈ 44 分、つまり 8 × 4 = **32 件**\ （``n_prescreen_keep = 32``）。
- 合計で約 48 分、時間の目安に収まります。**この合計は実測したステップ時間からの計算値で、既定値の実行を
  最後まで通して測ったものではありません。** 60 ステップでの収束は確認しておらず、
  ``relax_fmax`` に届かない場合があります。
- ナフタレンより大きい分子（OS-2SMe など）は 1 ステップが遅いため、同じ時間で回せる周数が減ります。

``relax_steps`` を 150 に増やすと 1 周が約 27 分になり、1 時間では 1 周（8 件）しか回せません。
緩和は収束しきらなくても、順位付けの前に候補を絞るには足りるという判断で 60 にしています。
本番では ``time_budget_min`` を長くする、空間群を減らす（``informed``）、
``n_procs`` を CPU コア数にあわせる、のいずれかで件数を増やしてください。

時間の目安の仕組みは次のとおりです。候補は ``n_procs`` 件ずつの周に分けて緩和し、1 周ごとに時間を測ります。
次の周に入る前に、残り時間（``time_budget_min`` の 90 % からそれまでの経過時間を引いたもの）を
それまでで最も遅かった周の時間と比べ、足りなければ残りの候補は緩和しません。
周ごとに確かめるので、2 周目以降が最初の周より遅くなっても早めに止まります。ただし、思いがけず遅い 1 周が
あると、その周の長さの分までは目安を超えることがあります。
**最初の 1 周は必ず実行する**\ （既定値のナフタレンで約 11 分、生成に約 4 分）ので、
``time_budget_min`` が約 15 分未満だと目安を超えます。

充填率の範囲について
~~~~~~~~~~~~~~~~~~~~

PyXtal が作る緩和前のセルは、実際の結晶（充填率 0.6〜0.8 程度）よりかなり疎で、
ベンゼンで約 0.46、ナフタレンで約 0.52 でした（どの空間群・どの乱数でもほぼ同じ値）。
そのため ``packing_range`` の既定は ``[0.4, 0.8]`` にしています。
PyXtal の体積係数 ``factor`` を 1.1 から 0.8 に下げて密にすることもできますが、
密にした分、重なりチェックで落ちる候補が増えます（ナフタレンで、重なりのない候補が
``factor = 1.1`` で約 2 割から、0.8 ではほぼ 0 になる）。このため既定の体積係数を採用し、範囲のほうを広げました。

制限事項
--------

- **分子は入力の配座で剛体です。** 配座の自由度（ねじれ）は生成の段階では振りません。
  緩和で多少は動きますが、``max_mol_rmsd`` を超えると捨てられます。
- **GFN2-xTB の順位では、近い多形を分けられないことがあります。** 特に双極子をもつ分子では、
  エネルギー差が方法の誤差より小さくなります。実験構造が生成できていても、順位が ``n_top`` より下
  （50 位より下なら比較の対象にもならない）になることがあります。
- **flip disorder は扱いません。** O と S が入れ替わった分子の混在（占有率が 1 でないサイト）は
  再現せず、「反転一致」（flip match）として別に報告するだけです。
- 置換元 CIF と実験 CIF は **disorder のない** ものが必要です。
- 緩和は力の収束まで行わないことがあり（``relax_steps`` で打ち切り）、エネルギーはその状態のものです。
- DFT による再評価や、スーパーコンピュータでの大規模な探索は含みません。
