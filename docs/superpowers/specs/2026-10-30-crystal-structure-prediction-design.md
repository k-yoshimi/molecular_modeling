# 元素置換分子の結晶構造予測：設計書

- 日付: 2026-10-30
- 背景資料: `refs/261013_nk_Molecular_Modeling_tool_Report.pdf`（加藤さん 2026/10/13 進捗報告）

## 1. 意図と背景

加藤さんは、2O-2SMe と 2S-2SMe（結晶構造は既知）の O/S を置換した OS-2SMe について、本ツールで結晶構造を予測しようとした。しかし次の症状が出た。

| 症状（報告より） | コード上の原因（2026-10-30 に確認） |
|---|---|
| 出力が置換元の結晶構造のコピーになる | Voronoi IoU は**格子ベクトルと分子重心だけ**から計算している（`source/voronoi_geom.py` の `_build_dict_seeds_cart` / `iou_via_union_cart`）。原子座標は使われない。最適化は「置換元の重心配置を回転させて新しい格子の重心配置に合わせる」だけなので、置換元と同じ格子なら回転はほぼ0、つまりコピーになる。 |
| Head-to-tail の分子反転が再現できない | 上と同じ理由。重心だけを見ているので、分子の頭と尻尾を区別できない。 |
| 1分子を選んで OS-i の格子で回すと、分子が不自然に圧縮される | `optimize_voronoi_overlap.py` が、体積比から決めた倍率 `s=(V_sys/V_dict)^(1/3)` を**原子座標そのもの**に掛けている（183行目）。そのため結合長が変わる。 |
| 分子がつながらず、断片が出る | GUI の分子保存（`gui/save_molecule_dialog.py` の `apply`）が、周期境界をまたぐ分子をつなぎ直さずに保存している（推測。実際の toml ではまだ確かめていない）。 |

つまり、今の仕組みは「置換元の詰まり方を新しい格子に写す」もので、置換元に引きずられない予測は原理的にできない。そこで、**格子も含めて候補を生成し、エネルギーで順位を付ける**仕組みに作り替える。

## 2. ゴール・非ゴール・アンチゴール

### ゴール
- 分子1つ（Gaussian 等で最適化した孤立分子の構造）を入力として、**格子定数・空間群・分子の向きと位置を含む結晶構造候補**を、エネルギー順のリストとして出力する。
- 置換元の結晶構造（O→S 置換したもの）は**候補の一つ**として扱う。答えとして固定しない。
- **成功の判定**: OS-2SMe の実験構造（OS-i、OS-ii）を見ずに予測を回し、**手元の PC で得た xTB の順位**で、上位の候補に OS-i か OS-ii に近い構造が入っていること（判定方法は 5.6 節）。
- 手元の PC で、**1回の予測が1時間程度**で終わること。
- 既存のバグ（原子座標の拡大・縮小、周期境界で分子が切れる問題）を直す。

### 非ゴール
- flip disorder（OS-i 7:3、OS-ii 6.5:3.5）の再現。今回は範囲外とする【Claude の判断】。ただし、上位候補について、分子を反転させた構造とのエネルギー差を出せるよう、拡張できる形にしておく。
- スパコンでの計算（DFT）。今の段階ではスパコンは使わない。DFT の入力やジョブスクリプトの生成も今回は作らない。上位候補の CIF は出力するので、必要になれば既存の `write_structure` で QE / VASP の入力を作れる。
- 分子の柔軟性（配座の探索）。**候補生成の段階**では分子を剛体として扱い、-SMe 基の配座は入力分子の構造で固定する。緩和の段階では原子を動かしてよい（5.4 節）。
- 結晶構造予測（CSP）の完全な一般化。対象は、Z' = 1（必要なら 2）の有機分子結晶とする。

### アンチゴール（技術的には動いても失敗とみなすもの）
- 出力がいつも置換元の構造に収束する。
- 分子の結合長や形が、物理的な理由なく変わってしまう（今の Voronoi 最適化での一律の拡大・縮小のようなもの）。緩和による自然な小さな変化は許すが、入力分子からの変形量は記録し、閾値を超えた候補は除く（5.4 節）。
- 断片化した分子や、原子が重なった構造が上位の候補に残る。
- 加藤さんが、何が起きているかを追えない（候補ごとのエネルギー、密度、由来が分からない）。

## 3. 制約

- 既存の構成を活かす: Python 3.11 以上、ASE、パッケージ `molecular_modeling`（`source/`）、TOML による入力、pytest、ruff、mypy。
- ライセンスは LGPL-2.1-or-later。追加する依存ライブラリは、これと両立するものに限る（PyXtal: MIT、tblite: LGPL-3.0 で、どちらも可）。
- すべての計算を**手元の PC（macOS）でコマンドラインから**実行する【コマンドラインにした点は Claude の判断】。1回の予測は1時間程度に収める（ユーザーの指定）。
- 既存の GUI、`write_structure.py` による QE / VASP / CIF 出力は残す。
- ドキュメントは日英の両方（既存の `docs/ja`、`docs/en` に合わせる）。

## 4. 決まっていること（ユーザーが決めたこと）

- 格子も予測対象に含める。
- 評価にエネルギー計算（力場、xTB、DFT）を持ち込んでよい。
- Voronoi は「分子の初期位置（向き）を与える」ものとして作った、というのが元の意図（ユーザー）。重ねる対象を変えて、**向きの初期値を作る生成器**として新しい流れに組み込む（5.2 節）。結果が出なければ置き換えてよい。
- 既存のバグ（5.8 節）は修正する。
- 成功の判定は、OS-i と OS-ii の実験構造との答え合わせで行う。順位は xTB で付けたもの（スパコンは使わない）。
- 探索条件は2つのモードを用意する。**ブラインドモード**は実験構造の情報を使わず、既定の空間群リストで探す。**情報ありモード**は、既知の空間群、Z、Z' を探索条件として与える。
- 1回の予測にかける時間は1時間程度。

## 5. 仕組み

```
分子 (xyz/toml) ─┐
                 ├─► [1] 候補生成 ─► [2] 重なりチェック ─► [3] 事前ふるい + 緩和 + 順位付け ─► [4] 重複除去 ─► [5] 出力（順位表 + CIF）
置換元 CIF ──────┘   (PyXtal ランダム / Voronoi 向き /     (剛体分子間エネルギー → GFN2-xTB)
                      置換元由来)
```

### 5.1 入力（新しい `input/csp.toml`）

- `molecule`: 分子ファイル（`data/<name>.toml` か `.xyz`）。孤立分子の直交座標。
- `mode`: `blind` または `informed`。`informed` のときは `space_groups`、`z`、`z_prime` を実験値で与える。`blind` のときは既定のリストを使う。
- `space_groups`: 試す空間群のリスト。既定値は有機結晶で頻度の高いもの（P2₁/c、P-1、P2₁2₁2₁、C2/c、P2₁、Pbca）【Claude の判断】。
- `z_prime`: 既定は 1。2 も指定できるようにする（OS-i、OS-ii が Z' = 2 の場合に情報ありモードで使う。計算量が増えるため、ブラインドモードの既定には入れない）。
- `n_candidates_per_sg`: 空間群ごとに作る候補の数。
- `seed_structures`: 置換元の CIF と、置換規則（例: 特定のサイトの O→S）。省略可。
- `density_range` / `volume_factor`: 生成する格子体積の幅。
- `rng`: 再現性のための乱数シード。
- `generators`: 使う生成器とその割合（`random`、`voronoi`、`seed`）。
- `screening`: 閾値、事前ふるいで残す件数、GFN2-xTB で緩和する件数、緩和の最大ステップ数、並列数。
- `time_budget_min`: 時間の目安（既定 60 分）。各段で処理する件数は、この目安から決める。

### 5.2 候補生成
- PyXtal の分子結晶生成（`pyxtal.from_random(3, sg, [mol], [Z])` 相当）で、空間群ごとに格子・向き・位置を振る。
- 置換元由来の候補: 置換元 CIF は、disorder を取り除いて秩序化したもの（加藤さんが VESTA で処理したもの）を前提とする。部分占有のある CIF には対応しない【Claude の判断】。置換元 CIF を読み、周期境界をまたぐ分子をつなぎ直す。分子ごとに、元の分子を入力分子に**剛体として重ね合わせ**（Kabsch 法。O/S の違いは原子の対応付けで扱う）、置き換える。格子は置換元のまま、または体積比でスケールしたものを使う。原子座標は拡大・縮小しない。等価な O サイトが2つあるので、O→S の割り当ては「全分子が同じ向き」の2通りを作る。分子ごとに向きを混ぜた組み合わせは作らない【Claude の判断】。
- **Voronoi で向きを決めた候補**（ユーザーの元の意図を活かす生成器）:
  - 格子と分子の重心は、PyXtal が作った候補、または置換元の結晶を体積でスケールしたものから取る。
  - 重心から各分子の Voronoi セルを作り（既存の `voronoi_geom.py` の `_build_system_seeds_cart` と `_voronoi_cell_vertices_halfspaces_cart` を使う。単位胞で切り取らないセルが必要なため）、**分子そのものの形**とのIoUが最大になる向きを探す。分子の形は、原子をファンデルワールス半径でふくらませた凸包で表す。比較のときだけ、その形を Voronoi セルの体積に合わせて拡大・縮小する。**原子座標は拡大・縮小せず、剛体として回転させるだけにする**。
  - 向きの探索は、既存の Euler 角グリッドと Nelder–Mead の流れを流用する。今の「置換元の重心配置の Voronoi セルと重ねる」IoU は使わない。
  - 細長くほぼ対称な分子では頭と尻尾が区別できないので、IoU が最大の向きと、それを分子の重心を通り分子面に垂直な軸（重原子の慣性の広がりが最も小さい主軸）のまわりに 180° 回した向きの2通りを候補にする。この回転で分子の両端（OS-2SMe なら O の端と S の端）が入れ替わり、分子面は保たれる【Claude の判断、改訂: 当初の「長軸のまわりに 180°」では両端が入れ替わらないため】。
  - PyXtal が作った骨格では、空間群の対称性を保つため、向きを決めるのは非対称単位の分子だけにし、残りの分子は空間群の操作で作る（PyXtal の `mol_site.orientation` を書き換える。2026-10-30 に動作を確認済み）。置換元由来の骨格は P1 として扱い、分子ごとに向きを決める【Claude の判断】。
  - 答え合わせのときは、ランダム由来・Voronoi 由来・置換元由来のどれが実験構造に近かったかを報告する。これで Voronoi の効果を数字で示せる。
- どの候補にも、由来（生成器、空間群、乱数シード、または置換元の名前）を記録する。

### 5.3 重なりチェック
- 分子間の原子間距離が「ファンデルワールス半径の和 × 係数」を下回る候補を捨てる。
- 分子のつながりを結合判定で確かめ、分子が切れている候補を捨てる。

### 5.4 軽量緩和と順位付け
- **2026-10-30 の実測**（Apple Silicon、Python 3.13、tblite 0.8.0、PyXtal 1.1.5）: tblite の ASE calculator には **GFN-FF がない**（GFN1-xTB と GFN2-xTB のみ）。GFN2-xTB の周期系計算は、72 原子のセルで1ステップ約 0.3 秒、格子込みの FIRE 60 ステップで約 18 秒。PyXtal の候補生成は1件あたり数十ミリ秒。
- これを踏まえ、手順は次のようにする【Claude の判断】:
  1. 数千件を生成し、重なりと密度（分子体積から見積もった充填率 0.6〜0.8）でふるい分ける。
  2. **剛体分子のままの簡易な分子間エネルギー**（元素ごとの LJ パラメータ。UFF の値を使う）で順位を付け、上位 100〜200 件に絞る。
  3. 残った候補を **GFN2-xTB（tblite）で格子ごと緩和する**。ステップ数に上限を付け、複数のプロセスで並列に回す。
  4. 緩和後の GFN2-xTB エネルギーで順位を付ける。
- 具体的な件数とステップ数は、実装者が OS-2SMe 程度の大きさの分子で実測して決める。設定ファイルで変えられるようにする。
- xtb バイナリ経由の GFN-FF は、今回は使わない。後から別の計算手段を足せるよう、エネルギー計算の部分は差し替えられる形にしておく。
- 格子込みの緩和には、ASE の `FrechetCellFilter` と FIRE または BFGS を使う。原子はすべて動かしてよい（剛体のまま緩和する最適化器は作らない）【Claude の判断】。
- 緩和後、各分子を入力分子に重ね合わせたときの RMSD（水素を除く）を記録する。0.5 Å を超えた候補や、結合が切れたり新しくできたりした候補は除く【Claude の判断。初期値で、調整する】。
- 記録する項目: 1分子あたりのエネルギー、密度、空間群（緩和後に spglib で再判定）、由来。

### 5.5 重複除去
- pymatgen の `StructureMatcher`、または PyXtal の比較機能を使い、同じ構造をまとめる。

### 5.6 答え合わせ（検証用。本体とは別のスクリプト）
- 実験構造（OS-i、OS-ii の CIF）と上位 N 件の候補を比べる。
- 指標は COMPACK 方式の RMSD₁₅（15分子クラスターを重ねたときの RMSD）、または `StructureMatcher` で一致するかどうか。成功の基準は「上位 20 件以内に、RMSD₁₅ < 0.8 Å の候補がある」とする【Claude の判断。初期値で、調整する】。
- xTB の順位では基準を満たさなくても、上位 N 件より下に一致する候補があれば、それを報告する（生成はできたが順位付けで外れたのか、そもそも生成できなかったのかを区別するため）。基準を満たさなかったときに手法を変えるかどうかは、この報告を見て決める【Claude の判断】。
- 実験構造の flip disorder は、占有率の高い成分だけを使って比べる。O と S を入れ替えた（分子を反転させた）候補が一致した場合は、「反転一致」として別に記録し、成功とは数えない【Claude の判断】。

### 5.7 出力
- `csp_out/candidates.csv`: 順位、エネルギー、密度、空間群、由来
- `csp_out/<rank>_<id>.cif`
- 進み具合のログ（各段で何件残ったか）

### 5.8 既存コードの修正（方針と関係なく行う）
- `optimize_voronoi_overlap.py`: 原子座標への倍率 `s` を掛けるのをやめる（Voronoi セルの比較にだけ使う）。既存の Voronoi パイプライン（`run.py`）は残す。新しい流れでは、Voronoi の幾何計算部分（`voronoi_geom.py`）を再利用する。
- `gui/save_molecule_dialog.py`: 保存する前に、周期境界で切れた分子をつなぎ直す（最小像規約による結合グラフで展開する）。
- `build_system_from_toml.py`: 重心の計算方法を統一する（GUI は質量で重み付けした重心、ビルダーは単純平均を使っていて一致していない）。
